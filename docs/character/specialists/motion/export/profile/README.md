documentation are Stage4 source. The frozen1f motion and9da exporter stay intact.
Stage2 owns body/material/finish, Stage3 owns future motion/physical cloth/FX,
and Stage1 alone runs native jobs and publishes. No generic retarget or new
character is invented by this finite seam.

`character_profile.mjs` supports `inspect`, `export-review`, and `emit-native`.
Every root is explicit, absolute and D-backed. Existing ancestors are resolved
through the real filesystem, file paths are source-relative, and fresh write
roots cannot overlap source/private/reference inputs or a public directory.
Profiles validate exact source/config/input SHA256 values. There are no native
execution or release switches. Unknown and repeated CLI options fail.

Historical source bindings cover the existing importer/exporter, PNG codec,
config, validator, packer, actual required Player clips and ClipPlayer. Native
bindings pin twelve entry/guard/request/licence files plus content digests for
the producer's Python/JSON dependency trees: `tools/pixel-pipeline`,
`tools/art-construct`, and `art/rosace`. Added or changed matching source files
fail; source tree symlinks fail. Files are copied only by the private proof
preparation, with identical bytes. A Git-backed executing source root records
its observed Git head; native source must be exact545. Historical frozen pins
can be used from a descendant of9da. A cold code/config snapshot has no Git head
claim; its identity is its checked content closure plus original Git provenance.
