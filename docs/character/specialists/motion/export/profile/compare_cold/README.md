# Immutable cold profile comparator

This helper compares the bound545 raw cold outputs; it never executes a producer,
Blender, setup, app/model/GPU or new native request. Original9b/b072, requestd798,
binding8ce3, source/private/reference copies and producer files remain unchanged.
It has one production CLI argument: a fresh private report root.

```powershell
python art/rosace/specialists/motion/export/profile/compare_cold/compare_cold.py --out D:/Dex/Automation/reports/dex-suite-resumption-20260930/lanes/rosace-motion/proofs/cold-comparison-v1/<fresh-comparison-report>
```

Run imports, syntax, image processing and prover through existing resource gate
owner `rosace-cold-comparison-build`, TimeoutSeconds10 or60, normal3/throttle1.
No policy/lease/reservation changes. Small static JSON/header/source reads need
no gate. Angle-bracket report name is a placeholder, not an executed comparison.

The request and sibling binding are fixed paths and exact SHA256 constants. The
fresh cold output is taken solely from the single literal `--out` in that pinned
argv and must match binding.renderRoot/reconstruction-raw. CLI has no producer,
input-root override, fixture mode or bypass. Report roots must be fresh, D-backed,
outside every consumed root and outside public trees. Missing required cold
outputs produce an explicit missing receipt and exit2, never success.
Candidate comparison mismatches produce comparison.json with comparisonPassedfalse
and exit1: file plus JSON pointer, dimension values or first differing RGBA pixel/
channel/sample values. Frozen-input and path-admission failures still fail before
creating output. No mismatch is ignored or converted to an equality claim.

Before comparison the helper verifies12 sourcePins,1 privatePin, all full source
tree membership/file bytes (174/48/717), all23 frozen referencePins and the SAME23
pins against the genuine original545 reference root. Tree checks compare the
trusted filelists, count and every SHA directly; they do not regenerate or change
the old aggregate digest algorithm. Reparse/symlink/junction paths reject before
reading or traversing; resolved file paths remain in the explicit bound root.

`depth2-supplement.json` is new scoped input, explicitly separate from old pins
and immutable request. It binds the two original545 depth2 PNGs and sizes. Thus
comparison covers14 PNGs (id/normal/depth/depth2/light/beauty/noise at80/144) and9
JSONs (meta/reconstruction/window_geometry/haft_grips at both sizes plus full
retained-face-preservation). Old expected21 remain21; supplemental depth2 adds2.
Pinned R2 finished stills are verified input-cohort evidence, not new output.

PNG comparison validates signature/chunk bounds/CRC/IHDR, requires noninterlaced
8bit colorType6 RGBA and single frame, and checks decoded dimensions and every
RGBA8 sample including RGB under alpha0. No conversion, resampling or numeric
tolerance is used. Original real dimensions are304×472 at80 and508×812 at144,
exactly bound canvas×ss4. Encoded SHA differences are reported separately and do
not decide decoded pixel equality.

All JSON parsing rejects duplicate keys, NaN/Infinity and overflow nonfinite
floats. Comparison requires identical types, object key sets, arrays and finite
scalar values. Int1, float1.0 and booltrue differ. All113bone4×4 matrices,
geometry/window/rim/effectivePose/haft joints+joints3d/contact/material/framing,
camera/ppm and full4737 retained-face records are compared exactly. There is no
timestamp, digest, unknown-field or nondeterministic exemption.

Only `/pose_file` and `/d9/r2` in each meta.json may relocate. Every reference
value must equal the concrete original native source path; every cold value must
equal the exact new request-bound sourceRoot plus its relative path. Their source
file SHA pins are verified. Four observed relocations are recorded explicitly.
Matching pixels with old metadata paths still fail. No prefix/string replacement
normalizes other fields or paths. Bound45/8 camera, ss4, canvas/anchor/ppm and the
seven pass names are checked independently too.

The bounded prover copies genuine pinned reference files only to its fresh owned
utility directory. It exercises exact comparison, an encoding-only PNG variation,
the four path leaves and meaningful pixel/dimension/header/JSON/rig/geometry/pin/
containment negatives. Utility roots are passed to comparison functions directly;
the production CLI accepts no utility input. Nothing populates actual coldRoot or
creates a positive native cold report. Original producer execution is still a
separate sole-delivery fact.

Every result says comparisonOnlytrue, nativeExecutionProvenfalse and
fullPipelineProvenfalse. Even an exact raw match proves only compared bytes and
authorized relocation. It proves no execution provenance, appearance9, finished
or six-still post, physical cloth, accepted character, full pipeline or World.
Current545 appearance was rejected. Stage1 executes the immutable request and
then supplies actual execution provenance; full Stage2/3/World gates remain.
