## Window2: native geometry experiment

Window1's gold/skin finish letters were rejected as badges. Window2 changes
construction: remove only anterior bodice faces inside the sternum-anchor
diamond, retain the actual body skin underneath, and create a separate gold
strip outside the new cloth boundary. Half width44mm, existing anchor span
about118mm, rim radial width5mm. No skin-colored fill or painted-hole proof.

`nx_window_mesh_blender.py` wraps the reviewed H1 driver at hand scale1.0,
unchanged R2 idle, head1.10, ss4 and both144/80. Geometry installs after R2
runtime edits and before pose/render. It copies only bodice mesh data in
memory, deletes faces with `FACES_ONLY`, and asserts unchanged original vertex
indices/coordinates, weights/groups, shape keys, point attributes, materials
and IDs plus every retained face/UV/corner datum. Existing open garment edges
must stay unchanged; the new boundary must be one closed loop. Body/collar/
cross/plate invariants are protected. It never saves a blend. Process-local
hooks and original mesh pointers restore on exit.

The gold ring follows the cut boundary, receives matching deformation groups,
shape-key deltas and AO variants, and uses the existing gold shader. Its
normals face anteriorly. Animated/driven key state is refused until an explicit
synchronization route exists. Native qualification must check the installed
RNA, BMesh data preservation, active-shape fit, rim depth/normals and framing;
passing source tests does not establish these. Whole-face selection may be
jagged at sprite scale. The method can fail, and its guards must remain intact.

The API enum was checked against the [Blender5.1 BMesh operators documentation](https://docs.blender.org/api/5.1/bmesh.ops.html#bmesh.ops.delete).
The installed runtime's behavior remains unverified by the source owner.

`window_mesh_post.py` consumes genuine fresh native control/candidate passes
and runs unchanged R2 finish. Disabled control must reproduce preserved R2
pixels exactly. Candidate must reveal more actual `body`/`skin` ID subpixels
inside the projected aperture than control. It records native gold coverage,
all finished changes outside the window box and alpha differences without
discarding them. Skin ID gain is geometry evidence; continuous thin gold rim,
literal cloth termination directly below the collar cross and appeal require
actual144/80 pixels, outfit14 comparison and three fresh critics. Stills prove
no motion. No native window output exists yet.

`art/rosace/next/window-mesh-request.json` is the explicit finite four-still
delivery request. Native/GPU belongs only to delivery at a free resource
boundary, with world priority preserved. Resolve wrapper/R2/private paths to
the executing frozen worktree and use separate Blender processes per mode.
Do not stack hand, physics, pose, headtilt or face changes into this comparison.

## Face2: actual finish-only result, unpromoted

The experimental F1 eye seed was retained for comparison with exact R2.
Face2 coordinated the projected eyeline (slope0.192), tapered lids/brows,
shared iris offset and skin-only cheek/jaw finish. Actual R2 head geometry,
turn and pose stayed unchanged; original mouth cells were preserved. This is
authored deterministic pixel construction on genuine R2 raw passes, with no
image model or fresh-native claim.

The first guard caught global skin requantization coupling: intermediate
changes leaked onto body pixels. The explicit face-region composition keeps
the final remainder exact R2, preserves intermediate files and reports56/1
discarded outside-face changes at144/80. It changes93/18 final pixels, all in
the declared face box; final alpha and outside-face differences are0. R2
controls reproduce0px at both sizes. Mouth cell coordinates/colors are exact
control copies. Raw hashes and post diagnostics are in private proof.json.

Three fresh fork-none critics viewed all six actual neutral panels plus six
appropriate actual old/new reference sheets. Key: A=Face2, B=F1, C=R2.
Form: B>C>A at both sizes. Craft: C>B>A at144; B=C>A at80.
Appeal: B leads at both sizes; Face2 does not beat the seed. None finds face9.
Heavy/compressed lids and eye/cheek fusion cost openness, especially at80;
the shared weak gaps remain articulated hand contact, crowded waist/outfit
boundaries and weight-bearing pose. No average, global gain or promotion.

Actual proof: private `review/rosace/face2-2/proof.json`; neutral panels and
form/craft/appeal reports: `review/rosace/face2-panel/`. Face2 is preserved as a
failed/unpromoted construction. Do not stack it into the native window or
continue a mouth/lid microloop as proof of facial parity. The queued coherent
pose and matched body waist diagnostics remain separate useful next evidence.
