## How it was checked

1. The desktop lane's handoff record names the A-backed release file, its size
   and SHA-256; the package record, publish log and published receipt agree.
2. The release file was hashed again: size and SHA-256 match.
3. dexClient's own `scripts/check-channel.cjs` read the live channel with the
   pinned trusted key: pointer, both product manifests and the catalogue verify.
4. The signed pointer's dexClient installer entry (bytes, SHA-256, SHA-512) and
   the signed manifest's single file entry name the same file. The feed copy at
   `https://updates.dex.place/dexclient/dexClient-Setup-0.4.23.exe` was fetched
   and is byte-identical to the release file.
5. The file was copied into `D:\Dex\Servers\dex.place\downloads` under a temporary
   name, re-hashed, then renamed, with its ASCII sidecar:

   ```text
   36313368dd7cb92692a8320f398391a4d57266cb30aa48ad3c270e1ac7961ff9  dexClient-Setup-0.4.23.exe
   ```

6. The site tests hash the host file against the catalogue. A local `ops/server.mjs`
   origin served it as an attachment with the full byte count and matching
   SHA-256, and answered a Range request with 206.

No fresh friend-machine install, stable-channel qualification or code signing
is claimed here; those stay with the desktop delivery owner.
