# Playable homepage and world embeds

The homepage's World controls previously returned to a CSS still frame. The approved
mount module was absent even though `/world/` was playable. World panels also requested
`?embed=world` without a site implementation, so visitors received another full header.

The completion uses the existing mount region, bars, scroll sheet and controls. A thin
`src/world/mount.ts` adapter reuses `/world/` in an isolated same-origin frame. It does
not construct another runtime or alter WorldUI, gameplay, saves, assets or the Enter
gate. The frame viewport fits inside the authored cinematic bars; parent canvas wheel
and vertical touch gestures scroll the existing sheet, while panel reading stays local.
The host invokes the existing `setAway` API for simulation/audio-state pause. The
runtime still owns rendering; GPU suspension or performance is not claimed.

Real loading/fade/backdrop readiness enables the frame. Before that it is inert,
excluded from tab order and pointer input; the CSS still and direct World link remain.
Failure shows a short honest status and keeps the website usable. Loading publishes
`aria-busy`. Covering a focused world moves focus to the existing main landmark, so
hidden world keys cannot change the visitor's sound choice. Back to World restores
canvas/panel focus and reuses the runtime. Pagehide/pageshow preserve browser Back
behavior; explicit teardown removes only this mount's handlers and frame.

Homepage `room`, `spawn` and explicit legacy `world` selectors propagate. Destructive
or automation flags (`fresh`, `go`, `manual`, `mute`, debug) do not. Saves remain the
existing same-origin `dex.world.v1` data. The adapter depends on the already-exposed
`__world.game` lifecycle; future World API changes must preserve or revise this contract.

Framed world pages hide only outer site chrome. Their content, typography, gallery,
full-size action, code controls and standalone layout remain authored. Internal page
links and gallery history carry the embed query; assets, feeds, downloads and external
URLs do not. A copied embed URL opened normally remains standalone. Embedded root
pages omit the world; their World link opens `/world/` at the top level.

The separately owned WorldUI Escape correction (`1acaa94d`) must be combined at
delivery. It preserves native child dialogs/popovers on the first Escape and returns
from an unhandled Escape. The site's own piece-page Escape marks its gallery navigation
handled and retains the embed query. No WorldUI source was changed by this lane.
