# dex.place service owner

Node ESM service for the v2 website. `node server/index.mjs` listens only on127.0.0.1:5191. The parent website gateway owns public HTTPS/proxying and startup integration. It can mount `createWebsiteService(...).handler` directly into its existing HTTP server and must await the returned idempotent `close()` during shutdown. The unused internal server does not need to listen. This module does not configure DNS/firewalls, publish a tunnel, create accounts at infrastructure providers or restart the shared identity backend.

## Configuration and data

- `DEX_SITE_PUBLIC_ORIGIN`: exact browser origin; default local `http://127.0.0.1:5188`. Set `https://dex.place` only for the reviewed public gateway. Non-loopback HTTP origins are refused.
- `DEX_SITE_API_PORT`: default5191, bound to loopback.
- `DEX_SITE_DATA_ROOT`: default `D:/Dex/Projects/dex-place-world/runtime-v2`, outside source/public. Preserve its existing ACL; do not publish or export it. `state-v1.json` is written by one service process with serialized atomic replacement; `.previous` retains the last snapshot. Unsupported/corrupt data refuses startup without rewriting the original.
- `DEX_SITE_OWNER_IDS`: explicit comma-separated verified provider IDs, empty by default. Email text and editable profile metadata never grant ownership. Enroll the actual owner only after verifying that identity.
- `DEX_SITE_EMAIL_READY`: remains false until the foundation owner proves real SMTP, confirmation and recovery. Setting1 is an additional website readiness fact; it never enables provider signup by itself. `DEX_SITE_OAUTH_READY` independently gates verified Google/PKCE readiness.
- Optional `DEX_SITE_LIVEKIT_URL`, `DEX_SITE_LIVEKIT_API_KEY`, `DEX_SITE_LIVEKIT_API_SECRET`: values must be resolved into the private process environment by the owning launcher from protected refs. No raw keys belong in an env file, public bundle, source or receipt. Missing configuration leaves voice honestly unavailable. Configuration presence is not cross-network media proof.
- Alternatively `DEX_SITE_LIVEKIT_CONFIG` points to the protected metadata-only provider file. `loadConfiguredVoice` resolves exactly the two approved UTF-16 WinCred refs through the owned helper into private process memory. `DEX_SITE_LIVEKIT_MODE=cloud` selects the verified Cloud forwarded-room topology; `native` is for a separately verified endpoint such as the repaired local SFU. Keep development and production data roots separate, and disable development Cloud voice or share the16-slot operational budget after promotion.
- `trustCloudflareProxy:true` (factory option), or `DEX_SITE_TRUST_CLOUDFLARE_PROXY=1`, permits rate accounting from a single valid `cf-connecting-ip` only when the immediate socket peer is loopback. It is off by default. Public HTTPS also requires the canonical Host; mutation Origin and CSRF checks remain independent.
- `DEX_SITE_KOFI_VERIFICATION_TOKEN`: optional process-only value resolved by the owning launcher from the finite proposed `wincred://DEX_PLACE_KOFI_VERIFICATION_TOKEN`; never put the raw value in an env/config/source file. `DEX_SITE_KOFI_MODE` is `quarantine` by default or `pending-review`. Neither mode automatically confirms money. Missing token disables intake with503; factory tests inject `{kofi:{verificationToken,mode}}` explicitly.

The existing `https://relay.dex.place` identity owns password login, `me` verification and refresh. Browser-only PKCE adapters use the same GoTrue provider at `https://auth.dex.place`, resolving only the existing anon-key WinCred ref through its owned private helper. Shared SMTP/GoTrue policy and relay deployment remain with `D:/Dex/AI/DexCodeSupabase`/foundation. The verified callback contract is in `D:/Dex/Projects/dex-place-world/coordination/shared-account-callback-contract.md`; the foundation reply records its narrow public callback allowlist and actual email proof.

Provider tokens and browser sessions are memory-only. Process restart expires website sessions; it does not change desktop sessions. Cookies are opaque, host-only, HttpOnly, SameSite=Lax and Secure on public HTTPS. Development cookies use a different name. Session lifetime is30 minutes idle, at most12 hours; browser cookie lifetime is30 minutes. Every mutation requires the bound CSRF token and exact allowed Origin. Private responses use no-store. The service never logs credentials or request bodies.

## Interfaces

GET `/api/account/session` returns `{user,csrf,capabilities,recoverySession}`. Account mutations are `sign-in`, `sign-up`, `sign-out`, `recover`, `resend`, `oauth`, `password`, `profile` under `/api/account/`. Callback is the fixed `/api/account/callback` route; it accepts a verified one-use code flow, never access/refresh tokens in URLs.

GET/POST `/api/progress` and POST `/api/progress/merge` use `{accountId,revision,eventId,progress}`; merge additionally requires explicit checkpoint/settings preference. Progress is client-reported exploration, not a permission, payment receipt or persistent boss-menu grant. Schema fields are allowlisted. Guest import is deliberate, idempotent and keeps an original merge snapshot. A new empty account cannot silently import a preexisting guest world through its first autosave.

GET `/api/treasury`, own `/history`, POST `/claims` and `/visibility` are distinct from owner `/admin`, `/admin/source` and `/admin/review`. Production starts empty. Only an authenticated configured owner can confirm an evidenced source record; amount/currency/source identity are rechecked against the reviewed snapshot. Claims/QRs/outgoing links never confirm money. Listing, alias and amount disclosure are separate opt-ins. Public subtotals include only amount-public records; no cross-currency sum or private amount delta is exposed.

POST `/api/webhooks/kofi` is the sole provider-authenticated exception to browser CSRF: it checks the Ko-fi shared token, form envelope and64KiB body cap before a durable receipt acknowledgement, without creating a browser session. Message/transaction retries deduplicate, conflicts remain reviewable, and exact integer minor units avoid rounding. Owner-only `/api/treasury/admin/receipt` prepares an evidenced pending source record or rejects a notification. Test/quarantine/conflict receipts cannot be prepared; donor name/email never become a public alias or account link. Ordinary notifications still need manual evidence and separate confirmation. Detailed official-source/account discovery, configuration and activation sequence:`D:/Dex/Projects/dex-place-world/coordination/kofi-receipt-activation.md`. Actual provider activation remains pending; do not send tests to the static public edition.

POST `/api/social/pose` accepts the authored `WorldPose`, not arbitrary simulation commands. `public/world/rooms-v2.json` owns allowed room bounds/revisions. Dynamic bridge/lift states are validated and admission matches the renderer's safe-support rules. Pose is capped at10Hz by the client and bounded server rate; up to8 nearby peers per audience. Inactivity60s starts a2s fade and revokes audio eligibility; stale connections expire12s. A connected dormant marker prevents keepalives from recreating an active ghost after62s; it retains only the latest transient pose, never a location trail. Movement or deliberate renewed voice opt-in can resume activity. Positions are never written to the durable store. `/person`, `/report`, `/leave`, and owner `/admin` implement persistent per-account blocks/mutes and operational moderation. Network failure withdraws voice and stops pose retries until explicit Retry.

Voice uses `/api/voice/join`, `/hold`, `/leave` with short-lived grants. Publication is audio-only and enabled only during a verified hold; server watchdog expires missing heartbeats after2.5s and stuck holds after60s. On Cloud, each voice join gets a fresh private room and a token scoped only to that room. The server forwards at most4 eligible speakers into it; mute/block/leave remove actual forwarded instances or delete that listener's private room. A listener cannot forward participants or join another listener's room with its token. Cloud `canSubscribe` applies only inside this controlled private audience, never an unrestricted shared world room. The native repaired-SFU alternative retains general `canSubscribe:false` and explicit server per-track grants.

The service reserves a maximum16 concurrent voice joins before asynchronous Cloud calls, including pending joins. With one original participant plus at most4 forwarded instances per private room, the conservative ceiling is80 participant instances. This is capacity accounting, not a claim that forwarded copies are unbilled. The configured Build plan is free, but actual provider usage/quota remains authoritative. Ghost presence remains usable when voice capacity is full. No recording/transcription/video or shared combat is added. Client gain/panning complements server authorization; it never substitutes for it. Raw received WebRTC playback needs the muted SDK media-element driver plus the single controlled WebAudio path, as the Brave pilot demonstrated.

## Browser exports

`account/index.ts` exports `AccountProvider`, `useDexAccount`, `AccountPanel`, `TreasuryPanel`, `OwnerPanel` and client helpers. `progress` from the hook is an envelope: restore its `.progress` only on initial identity load or explicit import, never every autosave. Successful explicit imports emit `CustomEvent('dex-progress-imported',{detail:WorldProgress})`. Use `saveProgress` for either guest or signed-in events; it keeps those storage scopes separate.

`social/index.ts` exports `SocialController`, `SocialPanel`, `VoiceController`, `VoicePanel`. Feed `setWorld(pose,{worldActive,focused,fullContent,hudOpen})`. Lightweight HUD focus retains eligible listening but cancels an existing keyboard hold. Full content/blur/leave stops capture and reception. GlobalV belongs to `VoiceController`; a dedicated mobile Talk control uses `press(true)` and `release()` on up/cancel/lost capture. Root's music manager remains separate.
