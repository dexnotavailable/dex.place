# Source-rate decoder integration

2026-09-07. Implemented only in `site/src/worldsite/audio.ts`, following root approval of `../source-rate-decode-20260907/PROPOSAL.md` and the corresponding source documentation update.

## Changed behavior

The manager now lazily creates one `OfflineAudioContext(2, 1, 48000)` to decode the reviewed 48 kHz asset family. It never renders an offline song. The returned source-rate buffer goes directly into the existing cache and live AudioBufferSourceNode. The single real-time AudioContext remains at its chosen output rate.

Reservation now uses the reviewed source rate, keeping the unchanged 64 MiB decoded-cache cap meaningful across high-rate hardware. Non-48 kHz metadata produces an explicit error before fetching; missing offline decoding produces an explicit Sound error. There is no implicit downsample route or fallback to expanded hardware-rate decoding. Decoded rate and channel count are verified before insertion. Existing post-decode cancellation/dispose checks remain in place. Dispose releases the decoder reference. Diagnostics expose `decodeSampleRate` separately from live `sampleRate`.
